Expression & template cheatsheet

Expression

Plain Python, evaluated against the current archive record. Any exception (bad syntax, wrong type, ...) is treated as "didn't trigger" -- it never crashes the alert.

  • Fields -- any field in the current archive record, by name. Using one that isn't present just means the alert quietly doesn't fire that round, it never errors. {% if archive_fields %} Your station's archive table actually has:
    {% for name, unit in archive_fields %} {{ name }}{% if unit %} {{ unit }}{% endif %} {% endfor %}
    {% else %} Common ones: outTemp, windSpeed, windGust, windDir, barometer, rain, rainRate, dewpoint, outHumidity, inTemp, UV, radiation, dateTime -- exact set depends on your station's schema. {% endif %}
  • Aggregates -- avg(obs, minutes), amin(obs, minutes), amax(obs, minutes), asum(obs, minutes): rolling aggregate over the trailing window ending at this record's time, read straight from the archive. None if there's no data in that window. Add unit='C' (or any unit from the list below) to convert the result, e.g. amax('outTemp', 30, unit='C') for the 30-minute max in Celsius -- note to_C(amax(...)) does not work, the aggregate only returns a bare number by then with no field name attached to say what unit it's in, which is exactly what the unit= kwarg is for.
  • Units -- fields are stored in whatever unit system weewx.conf is configured for, so a raw comparison like outTemp < 0 silently means different things on a US-unit vs metric station. To pin an expression to a specific unit regardless of that setting, convert first: to_C(obs), to_F(obs), to_kts(obs), to_mps(obs) convert that field's current value to Celsius / Fahrenheit / knots / meters-per-second. For any other unit, use the general form convert(obs, unit_name) -- e.g. convert('barometer', 'hPa'), convert('rain', 'mm'). All return None (never an error) for a missing field or a unit that doesn't apply to that field's type (e.g. to_kts('outTemp')). To convert a number you already have instead of the record's raw value, pass it as a third argument: to_kts('windSpeed', avg('windSpeed', 30)) -- or just use the aggregates' own unit= kwarg above, it's the same thing but shorter. {% if all_units %} Every valid unit name (what to pass as unit_name/unit=):
    {% for name, label in all_units %} {{ name }}{% if label %} {{ label }}{% endif %} {% endfor %}
    {% endif %}
  • Safe builtins -- abs(), round(), min(), max(), len()
  • Wind direction names -- compass(windDir) turns degrees into a direction name: NW. A second argument picks how many points: compass(windDir, 4) for N/E/S/W, 8 (the default) for NE/SE/SW/NW as well, 16 for NNE/ENE/... too. Takes either the degrees, compass(windDir), or the name of a field to read them from, compass('windDir'). Rounds to the nearest sector and wraps at 360, so 350 and 10 are both N. Returns None (never an error) for a missing or non-numeric value. Mostly useful in a template.
  • Time & date -- the record's timestamp, broken out as plain numbers in local time on the WeeWX host (the same clock {dateTime_str} uses, so DST is handled for you): hour 0-23, minute 0-59, minute_of_day 0-1439, weekday 0=Mon .. 6=Sun, day of month, month 1-12, yday day of year, 1-366, year. These describe the record being processed, not wall-clock "now" -- the same thing in normal operation, but not while catching up on backlogged records. If your station's archive table happens to have a field with one of these names, that real field wins and the time value isn't injected.
  • Constants -- True, False, None
  • Comparisons / logic -- < > <= >= == != and or not is is not
  • Examples
    outTemp < 32.0
    avg('windSpeed', 30) is not None and avg('windSpeed', 30) > 20
    to_C('outTemp') is not None and to_C('outTemp') < 0
    to_kts('windGust') is not None and to_kts('windGust') > 25
    amax('outTemp', 30, unit='C') is not None and amax('outTemp', 30, unit='C') < 0
    hour >= 22 or hour < 6 nights only
    weekday >= 5 weekends only
    100 <= yday <= 250 a season window
    to_kts('windGust') is not None and to_kts('windGust') > 25 and 6 <= hour < 20

Template

Each {...} is a full expression in the language above -- not just a field name -- optionally followed by : and a str.format() format spec. So aggregates, unit conversions and the time values all work inside a message, e.g. {avg('windSpeed', 30, unit='kts'):.1f}. Two extras are available here that are not available in the expression: {dateTime_str} (human-readable time) and {alert_id}. {{ and }} are literal braces. A placeholder that fails (typo'd field, bad syntax) is left as literal text (e.g. {oops}) instead of crashing the send.

Because a placeholder is a full expression, Python's A if cond else B gives you if/else in a message, and it chains for a multi-way choice -- see the wind-direction example below. Two limits: a placeholder ends at the first }, so no dicts or sets inside one, and only expressions work -- no loops, no statements.

Examples
Freeze warning! outTemp={outTemp:.1f}F at {dateTime_str}
Alert {alert_id} fired: windSpeed={windSpeed}
Wind {windSpeed:.0f} from {compass(windDir)}
Wind from {compass(windDir, 16)} ({windDir:.0f} deg)
{'Overnight' if hour >= 22 or hour < 6 else 'Daytime'} freeze at {dateTime_str}

Use single quotes for text inside a placeholder, as above. What you type here is stored as-is, so single quotes always work. Double quotes work too when typed here -- but the same alert written by hand into a users/<id>.json file needs them escaped as \", and pasting that escaped form back into this box leaves the backslashes literal: the expression then won't parse and you get {\"N\" if ...} in your message instead of N. Single quotes avoid the whole problem.

Long conditions can be broken across lines and indented, as in real code -- the expression is compiled wrapped in parentheses, so line breaks are just formatting.

Only channels that have a subject line use it -- email puts it in the Subject header, Telegram has no such thing and ignores it. Left blank it defaults to "WeeWX alert: <id>". It's a template too, so {outTemp:.0f} and friends work here as well.

Expression debugger

A scratchpad for the expression language: type anything and see what it evaluates to against the latest archive record -- a number, a bool, None, a string, or the error it raised. Handy for checking a field's current value (outTemp), what a conversion gives you (to_C('outTemp')), whether an aggregate has any data (avg('windSpeed', 30)), or just what hour is right now -- before wiring any of it into an alert. Nothing here is saved.
